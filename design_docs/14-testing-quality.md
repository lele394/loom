# 14 — Testing and quality strategy

## 1. Principles

- Test the **domain rules and the seams**, not the framework.
- Every bug fix adds a regression test.
- AI tests never hit the network: the fake provider is the default in tests.
- Deterministic time and IDs via injectable `Clock`/`IdGen` in the test context.
- A test that cannot fail meaningfully is deleted.

## 2. Pyramid

| Layer | Tool | Scope | Count target |
| --- | --- | --- | --- |
| Unit | Vitest | pure functions: diff, ranks, bibtex, markdown, citation parsing, slug/id, token budgeting | ~120 |
| Integration | Vitest + Fastify `inject` + temp SQLite | routes → services → DB → filesystem | ~70 |
| Golden | Vitest snapshots | daily diffs, prompt assembly, export manifests | ~15 |
| Contract | Vitest | API response shapes, error codes, SSE event sequence | ~10 |
| Frontend | none in v1 (manual checklist) | — | — |
| E2E | optional Playwright (not a release gate) | login → create note → search | 5 |

React components are intentionally thin; the expensive logic lives server-side and in pure helpers, which is where tests pay off. A Playwright suite is documented as an optional add-on to avoid a browser dependency in v1.

## 3. Test harness

```ts
createTestContext({
  seed?: (ctx) => Promise<void>,
  ai?: 'fake' | 'none',
  timezone?: string,
})
```

- Creates a temp data dir, opens a fresh DB, runs migrations, builds the app with the fake worker disabled (jobs run inline on demand via `ctx.worker.drain()`).
- Returns `{app, ctx, cleanup, login()}`; `app.inject()` for requests.
- `login()` performs setup/login and returns headers with cookie + CSRF.
- A `runJobs()` helper drains the queue deterministically.

Test DB uses `:memory:` where possible; filesystem/blob tests use a temp dir.

## 4. Fixtures

`tests/fixtures/`:

- `project.json`, `note-blocks.json` (all block types), `task-board.json`
- `paper.pdf` (small, 3 pages, public-domain text), `paper.txt`
- `refs.bib` (5 entries incl. unicode, braces, missing fields)
- `events.json` (mixed activity for diff tests)
- `backup-v1.zip` (generated by a script, checked in only if < 200 KB; otherwise generated in the test)

Seeding helper creates: 2 projects, 8 objects, 3 references with tags, 12 events across two days, 1 conversation.

## 5. Must-have test cases

### Auth
- Setup once; second setup → 409.
- Login wrong password → 401, same generic message; 6th attempt → 429.
- Unsafe request without CSRF → 403.
- Expired session → 401; logout-all invalidates other sessions.
- Password change invalidates other sessions, keeps current.

### Objects and notes
- Create note → objects row + note row + FTS row + activity event.
- Save with stale `expectedVersion` → 409 with `currentVersion`.
- Save with `force` → snapshot created, version increments.
- Wikilinks resolve same project first, are case-insensitive, and create backlinks.
- Restore a version creates a new version (history is append-only).
- Delete moves to trash; restore brings back blocks and links; purge removes rows but keeps events.
- Draft title empty is rejected on save (but allowed at create).

### Tasks
- Move reorders densely and logs one `task.moved`.
- Moving into a done column sets `completed_at`; moving out clears it.
- Cross-column move to another project's column is rejected.
- Deleting a column with tasks → 409.

### Literature
- Upload PDF → blob hash, attachment row, extract job; drain → text status ready, DOI detected but not applied.
- Duplicate upload → one blob, two attachment rows.
- BibTeX import creates references and skips duplicate cite keys with a report.
- URL ingest blocks `127.0.0.1`, `10.0.0.1`, `[::1]`, and a redirect to a private IP.
- Uploading HTML named `.pdf` is rejected by sniffing.

### Search
- FTS finds body text and returns a snippet; filters by type/project/tag.
- Deleted object disappears from results.
- Semantic search with fake embeddings ranks a known note in top 3.
- Hybrid fusion includes results unique to each engine.
- Query with FTS syntax (`"`, `*`, `NEAR`) does not error.

### AI
- Chat with fake provider streams ordered SSE events and persists user + assistant messages.
- Unknown citation indices are dropped; valid ones persist with locator.
- Provider error mid-stream yields `error` event, no dangling assistant message if no text.
- Conversation scope=selection includes only selected object chunks.
- Save-as-note creates a note and a `derived_from` link.
- Extract-tasks validates JSON and rejects invalid model output.
- AI disabled → status reports reason, chat returns 503.

### Journal
- Diff for empty day is empty and stable.
- Timezone boundary: events at 23:30 local belong to that local date.
- Create+update same object counts once as added.
- Regeneration archives the previous summary.
- Digest job is idempotent for the same key.

### Backup/export
- Backup passes verification; tampered zip fails.
- Restore into a fresh context reproduces counts, note blocks and blob hashes.
- Restore aborts before mutation on checksum mismatch, missing blob, newer schema.
- Retention keeps the newest, prunes the oldest.
- Export contains valid JSONL on every line and Markdown with front matter.

### Jobs
- Retryable failure retries with backoff; exhausted → dead.
- Non-retryable failure → failed immediately.
- Duplicate idempotency key → one job.
- Crash recovery requeues `running` jobs (simulated by direct DB update).

## 6. Golden tests

- `diff.golden.json` for 6 scenarios (empty, single project, multi-project, global objects, deleted, completed).
- `prompts.golden.txt` for chat and digest prompt assembly with fixed sources.
- `manifest.golden.json` for export/backup manifests with frozen clocks.

Golden files are reviewed when changed; diffs must be explained in the commit.

## 7. Static quality gates

```
npm run typecheck     # tsc --noEmit, strict
npm run test          # vitest run
npm run check:boundaries  # module imports, no repo cross-imports
npm run build         # vite build + server smoke import
```

Optional but recommended: Prettier (formatting), ESLint (React hooks rules). The repository ships with typecheck, tests, boundary check and build as the enforced gates; formatting is left to the editor to avoid configuration churn.

`scripts/check-boundaries.mjs` enforces:
- `src/server/modules/*` may not import `src/server/modules/*/repo.ts`.
- `src/web/features/*` may not import another feature's components.
- No `console.log` in `src/server` (use the logger).
- No raw `dangerouslySetInnerHTML` in the web app.

## 8. CI pipeline

```yaml
- npm ci
- npm run typecheck
- npm run check:boundaries
- npm run test -- --coverage
- npm run build
- npm audit --audit-level=high  (allowed to warn)
```

v1 baseline (measured 2026-11-16 on 81 tests): **64.3%** server line coverage overall, with **74.0%** on the auth service, **81.3%** on activity/diff and **80.9%** on backup/restore. The ≥85% target for auth and backup remains a v1.1 goal; global coverage is not a release gate because untested HTTP wiring dominates the denominator. Coverage is a signal, not a goal.

## 9. Manual release checklist

- [ ] Setup → create project → note → task → upload PDF on a fresh data dir.
- [ ] Theme switch with no flash; both modes readable; accent override persists.
- [ ] `Ctrl+K`, `Ctrl+Shift+Space`, keyboard board move.
- [ ] AI with a real local model: citations open the right page/block; ungrounded question refuses.
- [ ] AI with no provider: all non-AI paths work, clear degradation.
- [ ] Stop the server mid-note-edit: draft survives via localStorage; reload reconciles.
- [ ] Create backup, stop, move `data/` to a new directory, start, verify.
- [ ] Restore that backup into an empty instance; verify counts and a PDF.
- [ ] 375 px and 1440 px layouts; reduced motion; keyboard-only pass.
- [ ] `curl /readyz` shows healthy; logs contain no secrets.

## 10. Definition of done (per feature)

1. Requirements IDs referenced in the PR/commit.
2. Server validation, authorization and error codes implemented.
3. Activity event emitted; search index updated; export includes the data.
4. Loading/empty/error states in the UI.
5. Unit + integration tests, no network in tests.
6. Docs updated (design doc or ADR if a decision changed).
7. Typecheck, tests, boundary check, build green.

## 11. Deliberate testing gaps (v1)

- No browser automation in the release gate (manual checklist instead).
- No performance regression suite; targets are checked manually with seed data.
- No fuzzing of the markdown renderer or BibTeX parser (property tests are P2).
- No real-model evaluation automation; the manual eval checklist is used.
- No accessibility automation (axe); manual keyboard/contrast checks.
